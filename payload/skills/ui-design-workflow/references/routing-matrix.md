# 路由矩阵：这一页该守哪套规矩

② 阶段的核心动作。**先判页面类型，再定规矩**——同一份需求、同一个项目里，不同页面就该有不同的规矩。

## 怎么判类型

问一句："这个人打开这页，**成功长什么样**？"

| 他来这里是为了… | 类型 | 规范 |
|---|---|---|
| 决定要不要用 / 要不要买 | **落地页**（Persuade） | 落地页规范 |
| 完成一件工作、看数、管事 | **控制台 / 仪表盘**（Operate） | 产品规范 |
| 干活用的工具、编辑器、设置 | **工作台 / 工具页**（Operate） | 产品规范 |
| 在手机上随手用 | **移动端**（Operate / Persuade 视页面） | 产品规范 + 移动端约束 |
| 读懂一件事 | **文档 / 说明**（Read） | 可读性优先 |
| 欣赏作品本身 | **展示**（Experience） | 作品主导 |

一个项目里四种同时存在很正常。**一个工具产品的落地页仍然是落地页规范**，不要因为它属于某个"工具"就套产品规范。

## 四种规范对照

| | 落地页规范 | 产品规范 |
|---|---|---|
| 目标 | 让人决定、行动 | 让人把事办完 |
| 空间 | **大留白**、一屏一个主张 | **信息密度**、栅格对齐 |
| 标题 | **巨型标题**可接受，是主角 | **巨型标题要收起来**，标题是导航不是主张 |
| 密度 | 松 | 紧；一屏要放得下关键数据 |
| 一致性 | 每个 section 可以各有性格 | 组件、间距、颜色必须成体系 |
| 典型失败 | 太素、没主张、像模板 | **套了落地页那套** → 一屏放不下几个数、标题压住数字 |
| 动效 | 服务叙事，可以抢眼 | 服务反馈，别打断 |

**移动端附加约束**：触控目标够大、拇指可达区域、单手可用、考虑弱网与中断、避免 hover-only 交互。

## 落到产物

判完类型后，把结论写进设计产物，而不是留在脑子里：

- `design-system/<slug>/MASTER.md`：全局的颜色、字体、间距基数、圆角、组件规则。
- `design-system/<slug>/pages/<页面>.md`：只写**该页与 MASTER 不同**的地方（例：`console.md` 写"标题 20px、表格行高 32px、密度优先"；`landing.md` 写"首屏标题 72px、section 间距 160px"）。
- 页面文件**优先于** MASTER，读的时候先看页面文件在不在。

## 反例（视频里那个）

控制台被套上落地页规范 → 大留白 + 巨型标题 → 一屏放不下几个数据，标注数字被标题压住。

**不是规范越多越好，是不同的页面该有不同的规矩。** 整个项目才不会出现"落地页像官网、控制台也像官网"。
